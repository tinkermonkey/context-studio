# 02 Child Forms

Provide the ability to pass parent context into the create node forms to enable seamless hierarchy creation workflow.

## 02.1 Create Child Record Forms

Update the `domain_form` and `term_form` to allow optionally passing in the parent record:

### Domain Form Enhancement

- Allow optionally passing in the `layer_id` as a prop
- Optionally pass the full `LayerOut` object for better UX (parent context display)
- Add `mode` prop to explicitly indicate child creation mode

### Term Form Enhancement

- Allow optionally passing in either the `domain_id` or the `parent_term_id` as a prop
- Optionally pass the full `DomainOut` or `TermOut` parent objects for better UX
- Add `mode` prop to explicitly indicate child creation mode
- Auto-populate `layer_id` from the selected/provided domain

### Child Mode Behavior

- If the parent is passed via a prop, hide the controls for selecting the parent (only show the `title` and `definition` fields)
- Display parent context information at the top of the form (e.g., "Creating domain in layer: Data Architecture")
- Use consistent iconography to indicate parent type (Layers, Database, Hash icons)
- Maintain all existing validation rules while auto-populating parent relationship fields

## 02.2 Integrate Create Child Record Forms

Update the `layer_details`, `domain_details`, and `term_details` to include the ability to create child records:

### Button Placement and Design

- In the card sections detailing the hierarchy, include a `create` button to create a `domain` or `term` by showing a modal with the correct form
- Place the button in the upper right next to the badges displaying the node counts
- Use "+" icon with descriptive text (e.g., "Add Domain", "Add Term")
- Ensure responsive design: horizontal layout on desktop, stacked on mobile

### Modal Integration

- Create reusable modal component for child creation workflows
- Modal should contain the appropriate form (domain_form or term_form) in child mode
- Pass parent context (ID and full object) to the form
- Handle modal open/close state management

### Success Workflow

- On successful child creation, close the modal
- Display success toast notification
- Automatically refresh the parent detail view to show the new child
- Use TanStack Query cache invalidation for optimal performance

### Error Handling

- Keep modal open on form validation errors
- Display error messages inline within the modal
- Show toast notifications for network/server errors
- Provide clear feedback for all error states

## 02.3 Technical Requirements

### State Management

- Use TanStack Query for cache invalidation after child creation
- Implement optimistic updates where appropriate
- Ensure parent views automatically reflect new children

### Accessibility

- Implement proper ARIA labels for parent context
- Ensure keyboard navigation works throughout the modal workflow
- Provide screen reader support for parent relationship information
- Manage focus correctly when opening/closing modals

### Data Consistency

- Validate parent-child relationships on both client and server
- Handle edge cases (e.g., parent deletion while form is open)
- Ensure atomic operations for child creation

### Performance

- Minimize API calls by passing full parent objects when available
- Use efficient cache invalidation strategies
- Lazy load parent context only when needed
