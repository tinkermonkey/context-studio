## 01.2 NLP On Demand Panel Design

### Overview
The NLP On Demand Panel is a React component designed to analyze a user-provided string via the `/api/nlp_analysis` endpoint. The analysis is triggered by user interaction and supports debounced re-analysis when the input changes after the initial request.

### Component Architecture
- **Component Name:** `NlpAnalysisPanel`
- **Props:**
  - `text: string` – The string to analyze
- **State:**
  - `analysisResult: object | null` – Stores the API response
  - `loading: boolean` – Indicates if the request is in progress
  - `error: ApiError | null` – Error handling
  - `pendingText: string` – Tracks text changes for debounce

### UI/UX
- Uses Flowbite React for layout and UI elements (Button, Card, Spinner, etc.)
- Responsive design for desktop, tablet, and mobile
- Clean, technical presentation of analysis data (JSON or table format)
- Error messages displayed using ButterToast

### Behavior
1. **Initial State:**
   - Displays input text and an `Analyze` button
2. **On Analyze Click:**
   - Calls `/api/nlp_analysis` with the provided text
   - Shows loading spinner while awaiting response
   - Displays analysis result or error
3. **On Text Change After Analysis:**
   - Debounces API call by 1 second
   - Updates result on successful response

### API Integration
- Uses a type-safe API client (Axios + OpenAPI types)
- API call managed via a custom React hook (`useNlpAnalysis`)
- State and caching handled by TanStack Query
- Errors wrapped in custom `ApiError` class

### Error Handling
- All API errors are caught and displayed via ButterToast
- Graceful fallback if analysis fails (shows error, allows retry)

### Testing
- Unit tests for the hook and service
- Integration tests for the component (mock API)
- Test debounce logic and error handling

### Logging
- All API calls and errors logged via the `logger` utility

### Example Usage
```tsx
<NlpAnalysisPanel text={inputText} />
```

### Known Issues & Workarounds
- If the API is slow, user may see a spinner for extended periods; consider adding timeout and retry logic in future iterations.
