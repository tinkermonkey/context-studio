# 5.2 NLP Component Design

This document details the technical design for implementing the enhanced NLP Analysis components as specified in the requirements document [05.1_nlp_component_requirements.md](05.1_nlp_component_requirements.md).

## 5.2.1 Component Architecture Overview

### Design Principles
- **Existing API Integration**: Build upon the current spaCy-based `/api/nlp_analysis` endpoint
- **Modular Design**: Each component is self-contained and reusable
- **Type Safety**: Leverage existing TypeScript interfaces from the NLP service
- **Responsive Layout**: Use Flowbite React components for consistent styling
- **Progressive Enhancement**: Build MVP functionality first, then enhance
- **Error Resilience**: Graceful degradation when API data is incomplete

### Component Hierarchy
```
NlpAnalysisPanel (existing - enhanced)
├── TokenSelectionList (new)
├── NlpEntityAnalysis (new)
└── TokenNlpAnalysis (new)
    ├── TokenSenseList (new)
    └── TokenConceptChart (new)
```

## 5.2.2 Enhanced NlpAnalysisPanel Design

### Current State
The existing `NlpAnalysisPanel` component currently displays raw JSON analysis results from the spaCy-based `/api/nlp_analysis` endpoint. It needs to be enhanced to provide structured, interactive analysis while continuing to use the same API endpoint for data retrieval.

### API Integration
The design continues to use the existing NLP service infrastructure:
- **Endpoint**: `/api/nlp_analysis` (spaCy-based analysis)
- **Service**: `NLPService` class with methods like `analyzeText()`, `extractTokens()`, `extractEntities()`
- **Hooks**: `useNLPAnalysis`, `useTokenExtraction`, `useEntityExtraction`
- **Types**: Existing interfaces (`TokenData`, `EntityData`, `ConcepcyData`, `WordNetData`, etc.)

### Enhanced Architecture
```tsx
interface NlpAnalysisPanelProps {
  text: string;
  showRawData?: boolean; // For debugging/technical users
}
```

### UI Layout
```
┌─────────────────────────────────────────┐
│ [Analyze Button] [Show Raw Data Toggle] │
├─────────────────────────────────────────┤
│ Token Analysis                          │
│ ┌─────────────────────────────────────┐ │
│ │ [Token1] [Token2] [Token3] ...      │ │
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│ Entity Analysis                         │
│ ┌─────────────────────────────────────┐ │

│ ┌─────────────────────────────────────┐ │

```

### State Management

## 5.2.3 TokenSelectionList Component

### Purpose
Display non-stop words as selectable tokens for detailed analysis using data from the existing spaCy analysis.

### Interface
```tsx
interface TokenSelectionListProps {
  tokens: TokenData[];
  selectedToken: TokenData | null;
  onTokenSelect: (token: TokenData) => void;
}

// Using existing TokenData interface from NLP service
interface TokenData {
  text: string;
  lemma?: string;
  pos?: string;
  tag?: string;
  start?: number;
  end?: number;
  is_stop?: boolean; // spaCy provides this field for filtering
  concepcy?: ConcepcyData;
  wordnet?: WordNetData;
  sense2vec?: Sense2VecData;
}
```

### Implementation Details
- Filter tokens where `is_stop !== true` (using spaCy's stop word detection)
- Use Flowbite `Badge` components for token display
- Visual indicators for available data sources (WordNet, Concepcy, Sense2Vec) from API response
- Responsive grid layout for mobile compatibility

### UI Design
```tsx
<div className="flex flex-wrap gap-2">
  {filteredTokens.map(token => (
    <Badge 
      key={token.text}
      color={selectedToken?.text === token.text ? "purple" : "gray"}
      className="cursor-pointer hover:bg-purple-100"
      onClick={() => onTokenSelect(token)}
    >
      {token.text}
      {token.wordnet && <span className="ml-1">📚</span>}
      {token.concepcy && <span className="ml-1">🧠</span>}
    </Badge>
  ))}
</div>
```

## 5.2.5 TokenSenseList Component

### Purpose
Display WordNet synsets (word senses) with selection capability and definition preview, using data from the spaCy-based analysis.

### Interface
```tsx
interface TokenSenseListProps {
  wordnetData: WordNetData; // From existing NLP service
  onSenseSelect: (sense: WordNetSense) => void;
  defaultSelection?: number; // Index of default selected sense (0)
}

interface WordNetSense {
  synset: string;
  definition: string;
  examples?: string[];
  lexFile?: string;
  partOfSpeech?: string;
}
```

### Data Structure Enhancement
The existing `WordNetData` interface may need minor extensions to support the UI requirements:
```tsx
// Current interface from nlp.ts
interface WordNetData {
  synsets?: object[];
  lemmas?: object[];
  definitions?: string[];
}

// Enhanced interface for UI components (backward compatible)
interface WordNetSynset {
  name: string;
  definition: string;
  examples?: string[];
  lexFile?: string;
  partOfSpeech?: string;
  rank?: number; // For default selection (if provided by spaCy analysis)
}
```

### UI Implementation
```tsx
<div className="space-y-2">
  {senses.map((sense, index) => (
    <Card key={sense.synset} 
          className={`cursor-pointer transition-colors ${
            selectedIndex === index ? 'ring-2 ring-purple-500' : 'hover:bg-gray-50'
          }`}
          onClick={() => handleSenseSelect(sense, index)}>
      <div className="p-3">
        <div className="flex justify-between items-start">
          <div className="flex-1">
            <h4 className="font-medium text-gray-900">{sense.synset}</h4>
            <p className="text-sm text-gray-600 mt-1">{sense.definition}</p>
            {sense.examples && (
              <div className="mt-2">
                <p className="text-xs text-gray-500">Example:</p>
                <p className="text-xs italic text-gray-600">"{sense.examples[0]}"</p>
              </div>
            )}
          </div>
          <Badge color={selectedIndex === index ? "purple" : "gray"} size="sm">
            {sense.partOfSpeech}
          </Badge>
        </div>
      </div>
    </Card>
  ))}
</div>
```

## 5.2.6 TokenConceptChart Component

### Purpose
Visualize concept relationships from Concepcy data using a network diagram approach, displaying the relationships discovered by the spaCy-based NLP analysis.

### Interface
```tsx
interface TokenConceptChartProps {
  concepcyData: ConcepcyData; // From existing NLP service
  maxRelationsPerType?: number; // Default: 2
  onConceptSelect?: (concept: string) => void;
}

interface ConcepcyRelation {
  relation: string; // e.g., 'IsA', 'RelatedTo', 'PartOf'
  terms: string[];
  scores?: number[];
}
```

### Data Structure Enhancement
The existing `ConcepcyData` interface may need minor extensions:
```tsx
// Current interface from nlp.ts
interface ConcepcyData {
  related_terms?: string[];
  score?: number;
}

// Enhanced interface for chart visualization (backward compatible)
interface ConcepcyData {
  related_terms?: ConcepcyRelation[] | string[]; // Support both formats
  score?: number;
  central_concept?: string; // If provided by analysis
}
```

### Visualization Approach
Given the requirement to create a diagram similar to the concept net diagram, we'll use a simple force-directed layout:

#### Option 1: SVG-based Simple Network (Recommended for MVP)
```tsx
// Simple SVG implementation
<svg viewBox="0 0 400 300" className="w-full h-64">
  {/* Central node */}
  <circle cx={200} cy={150} r={20} fill="#8B5CF6" />
  <text x={200} y={155} textAnchor="middle" className="text-xs fill-white">
    {centralTerm}
  </text>
  
  {/* Related nodes and connections */}
  {relations.map((relation, idx) => {
    const angle = (idx / relations.length) * 2 * Math.PI;
    const x = 200 + Math.cos(angle) * 80;
    const y = 150 + Math.sin(angle) * 80;
    
    return (
      <g key={relation.relation}>
        {/* Connection line */}
        <line x1={200} y1={150} x2={x} y2={y} stroke="#6B7280" />
        {/* Relation node */}
        <circle cx={x} cy={y} r={15} fill="#10B981" />
        <text x={x} y={y+4} textAnchor="middle" className="text-xs">
          {relation.relation}
        </text>
      </g>
    );
  })}
</svg>
```

#### Option 2: React Flow Integration (Future Enhancement)
For more complex visualizations, integrate `reactflow` library:
```bash
npm install reactflow
```

### Implementation Details
- Limit to top N relations per type (default N=2)
- Use color coding for different relationship types
- Interactive nodes with hover states
- Responsive design with proper scaling

## 5.2.7 NlpEntityAnalysis Component

### Purpose
Display recognized entities with links to external knowledge bases and definitions, using entity data from the spaCy-based analysis.

### Interface
```tsx
interface NlpEntityAnalysisProps {
  entities: EntityData[]; // From existing NLP service
  onEntitySelect?: (entity: EntityData) => void;
}

// Using existing EntityData interface with possible enhancements
interface EntityDisplayData {
  text: string;
  label: string;
  confidence?: number;
  externalLinks: ExternalLink[];
  definition?: string;
  additionalInfo?: Record<string, any>;
}

interface ExternalLink {
  source: 'dbpedia' | 'wikidata' | 'freebase';
  url: string;
  label: string;
}
```

### UI Implementation
```tsx
<div className="space-y-3">
  {entities.map((entity, index) => (
    <Card key={index} className="p-4">
      <div className="flex justify-between items-start">
        <div className="flex-1">
          <div className="flex items-center gap-2">
            <h4 className="font-medium text-gray-900">{entity.text}</h4>
            <Badge color="blue" size="sm">{entity.label}</Badge>
          </div>
          
          {entity.dbpedia && (
            <div className="mt-2">
              <p className="text-sm text-gray-600">{entity.dbpedia.label}</p>
              <a 
                href={entity.dbpedia.uri} 
                target="_blank" 
                rel="noopener noreferrer"
                className="text-blue-600 hover:text-blue-800 text-sm flex items-center gap-1"
              >
                <ExternalLink className="w-3 h-3" />
                View on DBpedia
              </a>
            </div>
          )}
        </div>
        
        {entity.dbpedia?.similarity && (
          <div className="text-right">
            <p className="text-xs text-gray-500">Confidence</p>
            <p className="text-sm font-medium">
              {(entity.dbpedia.similarity * 100).toFixed(1)}%
            </p>
          </div>
        )}
      </div>
    </Card>
  ))}
</div>
```

## 5.2.9 Error Handling & Resilience

### Error Boundaries
Each component should gracefully handle missing or malformed data:

```tsx
// Component-level error handling
const TokenSenseList: React.FC<TokenSenseListProps> = ({ wordnetData }) => {
  if (!wordnetData?.synsets || wordnetData.synsets.length === 0) {
    return (
      <div className="text-center py-4 text-gray-500">
        <p className="text-sm">No word senses available</p>
      </div>
    );
  }
  
  // Render component...
};
```

### Loading States
```tsx
// Loading state for async operations
{isLoading && (
  <div className="flex justify-center py-4">
    <Spinner size="md" />
    <span className="ml-2">Analyzing token...</span>
  </div>
)}
```

### API Error Handling
Leverage existing error handling patterns:
```tsx
// Use existing InlineApiError component
{error && (
  <InlineApiError 
    error={error} 
    className="mt-2" 
    showDetails={isDevelopment} 
  />
)}
```

## 5.2.11 Performance Considerations

### Optimization Strategies
1. **Lazy Loading**: Load detailed analysis only when tokens are selected
2. **Memoization**: Use `React.memo` for expensive rendering operations
3. **Debounced Updates**: Prevent excessive API calls during text changes
4. **Virtual Scrolling**: For large token lists (future enhancement)

### Bundle Size Management
- Import specific Flowbite components to reduce bundle size
- Use dynamic imports for chart libraries if needed
- Optimize SVG assets and icons
