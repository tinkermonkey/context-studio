# 12.1 Configuration Management

Configuration should be managed as data and should not be embedded in code.

## 12.1.1 Configuration Inventory

During the design phase a thourough inventory of the codebase should be conducted to discover hardcoded configuration which should be made configurable.

All configuration should be centralized into `/config.py`.

## 12.1.2 Configuration Persistence

Each configuration element should have a default value and any config overrides should be persisted.

- Server level configuration should be persisted in a json file which is read at the start of app startup and updated any time the config is updated

- Configuration should be grouped into logical sections like `nlp`, `llm`, etc

- Configuration should be able to be updated at the field level using a dot notation to specific which element to update

## 12.1.3 Configuration API

Configuration should be able to be read and set via an API, allowing full access to discover and set all config from the ux:

- The API should allow setting values for individual config fields specified by dot notation

- API requests should be validated against the config schema
