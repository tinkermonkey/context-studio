# 9.1 NLP Enrichment API

Provide an API which will retrieve context from reference APIs and return it in structured format.

## 9.1.1 Layered Architecture

Build the core functionality of retrieving the context from the reference APIs using a re-useable python service which can be utilized by the API and also in other areas of the application.

## 9.1.2 Utilize Caching Proxy

Utilize the caching proxy setup for each reference API if it is enabled for that source. Proxy config should be coordinated with the NLP pipeline config which uses some of the same sources. The cache should be common to both use cases for the same upstream source.

## 9.1.2.1 Service Layer Architecture

The enrichment functionality must be implemented with clear separation between the service layer that performs the work and the API layer that provides access to it.

### 9.1.2.1.1 Service Layer Requirements

- **Reusable Service**: Core enrichment functionality must be implemented as a standalone service class that can be used by the API layer and other application components
- **Dependency Injection**: Service should be injectable and configurable to support testing and different deployment scenarios
- **Source Abstraction**: Service should abstract individual reference API implementations behind a common interface
- **Error Isolation**: Service should handle all upstream API errors and return consistent error information without exposing implementation details
- **Configuration Management**: Service should accept configuration objects that define which sources to use, timeout settings, retry policies, etc.
- **Async Support**: Service must support asynchronous operations to handle concurrent requests to multiple reference APIs efficiently

### 9.1.2.1.2 API Layer Requirements

- **Thin API Layer**: API endpoints should primarily handle HTTP concerns (request/response formatting, validation, authentication) and delegate business logic to the service layer
- **Request Validation**: API layer must validate all incoming requests using Pydantic models or similar validation framework
- **Response Formatting**: API layer must format service responses into consistent HTTP response structures with appropriate status codes
- **Error Translation**: API layer must translate service layer errors into appropriate HTTP status codes and user-friendly error messages
- **Rate Limiting**: API layer should support rate limiting and request throttling to protect upstream services
- **Authentication/Authorization**: API layer must integrate with existing authentication mechanisms if required

### 9.1.2.1.3 Interface Requirements

- **Service Interface**: Define clear interface contracts between API and service layers using type hints and documented method signatures
- **Configuration Interface**: Service configuration must be serializable and validatable to support dynamic reconfiguration
- **Result Interface**: Service responses must use consistent data structures (preferably Pydantic models) that can be easily serialized to JSON
- **Error Interface**: Define standard error types and error information structures that can be consistently handled across the application

### 9.1.2.1.4 Testability Requirements

- **Unit Testing**: Service layer must be testable in isolation with mocked dependencies for upstream APIs
- **Integration Testing**: API layer must be testable against the real service implementation 
- **Mock Support**: Service must support dependency injection of mock implementations for testing
- **Test Data**: Provide test data sets and mock responses for each reference API to support consistent testing

## 9.1.3 Reference API Support

Provide endpoints for retrieving data from upstream reference sources:

### 9.1.3.1 DBPedia.org

#### 9.1.3.1.1 Resource Data Retrieval
**Endpoint**: `GET /api/nlp_analysis/reference/dbpedia/resource`  
**Purpose**: Retrieve structured data from a DBpedia resource URL by converting it to a `data` url and fetching the data

**Parameters**:
```json
{
  "resource_url": "http://dbpedia.org/resource/Apple_Inc.",
  "format": "json"  // Optional: json, xml, rdf
}
```

**Response**:
```json
{
  "success": true,
  "source": "dbpedia",
  "resource_uri": "http://dbpedia.org/resource/Apple_Inc.",
  "data_url": "http://dbpedia.org/data/Apple_Inc..json",
  "retrieved_at": "2025-08-29T10:30:00Z",
  "data": {
    "http://dbpedia.org/resource/Apple_Inc.": {
      "http://www.w3.org/2000/01/rdf-schema#label": [
        {"type": "literal", "value": "Apple Inc.", "lang": "en"}
      ],
      "http://dbpedia.org/ontology/foundingDate": [
        {"type": "literal", "value": "1976-04-01", "datatype": "http://www.w3.org/2001/XMLSchema#date"}
      ],
      "http://dbpedia.org/ontology/foundedBy": [
        {"type": "uri", "value": "http://dbpedia.org/resource/Steve_Jobs"}
      ]
    }
  }
}
```

#### 9.1.3.1.2 Search API
**Endpoint**: `GET /api/nlp_analysis/reference/dbpedia/search`  
**Purpose**: Retrieve structured data from DBpedia by invoking the dbpedia `/search` API

**Parameters**:
```json
{
  "query": "Apple technology company",
  "limit": 10,
  "offset": 0,
  "format": "json"
}
```

**Response**:

{
  "success": true,

  "total_results": 25,
  "retrieved_at": "2025-08-29T10:30:00Z",
  "results": [
    {
      "uri": "http://dbpedia.org/resource/Apple_Inc.",
      "label": "Apple Inc.",
      "description": "American multinational technology company",
      "score": 0.95,
      "types": [
        "http://dbpedia.org/ontology/Company",
        "http://dbpedia.org/ontology/Organisation"
      ]
    }
  ]
}
```

#### 9.1.3.1.3 SPARQL Query
**Endpoint**: `POST /api/nlp_analysis/reference/dbpedia/sparql`  
**Purpose**: Retrieve structured data from DBpedia by invoking a SPARQL query via the `/sparql` endpoint

**Request Body**:
```json
{
  "query": "SELECT ?company ?founded WHERE { ?company a dbo:Company . ?company dbo:foundingDate ?founded . FILTER(?founded > \"2000-01-01\"^^xsd:date) } LIMIT 10",
  "format": "json"
}
```

**Response**:
```json
{
  "success": true,
  "source": "dbpedia",
  "query_type": "sparql",
  "retrieved_at": "2025-08-29T10:30:00Z",
  "results": {
    "head": {
      "vars": ["company", "founded"]
    },
    "results": {
      "bindings": [
        {
          "company": {
            "type": "uri",
            "value": "http://dbpedia.org/resource/Facebook"
          },
          "founded": {
            "type": "literal",
            "value": "2004-02-04",
            "datatype": "http://www.w3.org/2001/XMLSchema#date"
          }
        }
      ]
    }
  }
}
```

### 9.1.3.2 ConceptNet

#### 9.1.3.2.1 Query API
**Endpoint**: `GET /api/nlp_analysis/reference/conceptnet/query`  
**Purpose**: Retrieve structured data from ConceptNet `query` based on term or term and relation

**Parameters**:
- `start=/c/en/{term}` - Starting concept
- `end=/c/en/{term}` - Ending concept  
- `node=/c/en/{term}` - Any concept
- `rel=/r/{relation}` - Specific relation
- `limit=20` - Result limit
- `offset=0` - Result offset

**Examples**:
```
GET /api/nlp_analysis/reference/conceptnet/query?start=/c/en/apple&rel=/r/IsA
GET /api/nlp_analysis/reference/conceptnet/query?end=/c/en/fruit
GET /api/nlp_analysis/reference/conceptnet/query?node=/c/en/technology
```

**Response**:
```json
{
  "success": true,
  "source": "conceptnet",
  "query_params": {
    "start": "/c/en/apple",
    "rel": "/r/IsA"
  },
  "retrieved_at": "2025-08-29T10:30:00Z",
  "edges": [
    {
      "@id": "/a/[/r/IsA/,/c/en/apple/,/c/en/fruit/]",
      "start": {
        "@id": "/c/en/apple",
        "label": "apple"
      },
      "rel": {
        "@id": "/r/IsA",
        "label": "IsA"
      },
      "end": {
        "@id": "/c/en/fruit",
        "label": "fruit"
      },
      "weight": 8.0,
      "sources": [
        {
          "@id": "/s/wordnet/3.1",
          "label": "WordNet 3.1"
        }
      ]
    }
  ]
}
```

### 9.1.3.3 Wikidata

}
```

**Response**:
```json
{
  "success": true,

  "retrieved_at": "2025-08-29T10:30:00Z",

    "head": {
      "vars": ["item", "itemLabel"]
    },
    "results": {
      "bindings": [
        {
          "item": {
            "type": "uri",
            "value": "http://www.wikidata.org/entity/Q312"

          "itemLabel": {
            "xml:lang": "en",
            "type": "literal",
            "value": "Apple Inc."

        }
      ]
    }
  }
}
```

### 9.1.3.4 Schema.org

#### 9.1.3.4.1 Entity Retrieval
**Endpoint**: `GET /api/nlp_analysis/reference/schema-org/entity/{identifier}`  
**Purpose**: Retrieve structured data for Schema.org entities, including all properties and inherited properties from parent entity types

**Parameters**:
- `identifier` - URL-encoded Schema.org identifier (e.g., "Organization", "Person")
- `include_inherited` - Boolean to include inherited properties (default: true)
- `include_children` - Boolean to include child entity information (default: false)

**Examples**:
```
GET /api/nlp_analysis/reference/schema-org/entity/Organization
GET /api/nlp_analysis/reference/schema-org/entity/Person?include_inherited=true&include_children=true
```

**Response**:
```json

  "source": "schema_org",

  "retrieved_at": "2025-08-29T10:30:00Z",

    "id": "uuid-here",

      {

#### 9.1.3.4.3 Search Entities and Properties
**Endpoint**: `GET /api/nlp_analysis/reference/schema-org/search`  
**Purpose**: Search across Schema.org entities and properties using text or semantic search

**Parameters**:
- `query` - Search query string
- `search_type` - "entities", "properties", or "both" (default: "both")
- `limit` - Result limit (default: 20)
- `offset` - Result offset (default: 0)
- `similarity_threshold` - For semantic search (default: 0.7)

**Examples**:
```
GET /api/nlp_analysis/reference/schema-org/search?query=business organization&search_type=entities&limit=10
GET /api/nlp_analysis/reference/schema-org/search?query=address contact&search_type=properties
```

**Response**:
```json
{
  "success": true,
  "source": "schema_org", 
  "query": "business organization",
  "search_type": "entities",
  "total_results": 15,
  "retrieved_at": "2025-08-29T10:30:00Z",
  "results": [
    {
      "type": "entity",
      "identifier": "https://schema.org/Organization",
      "title": "Organization", 
      "definition": "An organization such as a school, NGO, corporation, club, etc.",
      "relevance_score": 0.95
    },
    {
      "type": "entity", 
      "identifier": "https://schema.org/Corporation",
      "title": "Corporation",
      "definition": "A business corporation.",
      "relevance_score": 0.87
    }
  ]
