# 8.2 Schema.org Implementation Design

This document provides a detailed implementation design for the Schema.org local access feature as specified in [08.1_schema_org_requirements.md](./08.1_schema_org_requirements.md).

## 8.2.1 Architecture Overview

The Schema.org integration will be implemented as a separate module with its own database, models, services, and API endpoints. This follows the existing patterns in the codebase while maintaining clear separation from the core dataset functionality.

### 8.2.1.1 Component Structure

```
schema_org/
├── __init__.py
├── models.py              # SQLAlchemy models for Schema.org entities and properties
├── manager.py             # Schema.org database manager (download, parse, ingest)
├── service.py             # Business logic service layer
└── api.py                 # FastAPI router with REST endpoints
```

## 8.2.2 Database Design

### 8.2.2.1 Database Location
- **Database file**: `schemaorg.db` in the application root directory
- **Connection**: Separate SQLite database with sqlite-vec extension for vector similarity search
- **Schema management**: SQLAlchemy declarative models (no migrations needed)

### 8.2.2.2 Entity Model (SchemaOrgEntity)

```python
class SchemaOrgEntity(Base):
    __tablename__ = 'schema_org_entities'
    
    # Primary key
    id = Column(String, primary_key=True, default=lambda: str(uuid.uuid4()))
    
    # Schema.org identification
    identifier = Column(String, unique=True, nullable=False, index=True)  # @id value
    
    # Content fields
    title = Column(String, nullable=False, index=True)  # rdfs:label
    title_embedding = Column(BLOB, nullable=True)       # Vector embedding of title
    definition = Column(Text, nullable=True)            # rdfs:comment
    definition_embedding = Column(BLOB, nullable=True)  # Vector embedding of definition
    
    # Hierarchy
    parent_identifier = Column(String, nullable=True)   # rdfs:subClassOf.@id
    parent_id = Column(String, ForeignKey('schema_org_entities.id'), nullable=True)
    
    # Metadata
    created_at = Column(DateTime, default=lambda: datetime.datetime.now(datetime.UTC))
    raw = Column(JSON, nullable=False)                  # Original schema.org JSON
    
    # Relationships
    parent = relationship('SchemaOrgEntity', remote_side=[id], backref='children')
```

## 8.2.3 Schema.org Manager Service

### 8.2.3.1 SchemaOrgManager Class

The manager handles all data operations including download, parsing, and database population.

```python
class SchemaOrgManager:
    def __init__(self, db_path: str = "./schemaorg.db"):
        self.db_path = db_path
        self.backup_path = f"{db_path}.backup"
        self.engine = None
        self.session_local = None
        self.source_url = "https://schema.org/version/latest/schemaorg-current-https.jsonld"
        
    def initialize(self) -> bool:
        """Initialize the schema.org database. Auto-populate if empty."""
        
    def is_populated(self) -> bool:
        """Check if the database is populated with schema.org data."""
        
    def get_status(self) -> Dict[str, Any]:
        """Get current status of schema.org database."""
        
    def refresh_data(self, force: bool = False) -> bool:
        """Download and populate fresh schema.org data with backup."""
        
    def _create_backup(self) -> bool:
        """Create backup of existing database before refresh."""
        
    def _restore_from_backup(self) -> bool:
        """Restore database from backup if refresh fails."""
        
    def _download_schema_org(self) -> str:
        """Download schema.org JSON-LD file with progress logging."""
        
    def _parse_jsonld(self, file_path: str) -> Tuple[List[dict], List[dict]]:
        """Parse JSON-LD file into entities and properties with progress logging."""
        
    def _populate_database(self, entities: List[dict], properties: List[dict]) -> None:
        """Populate database with parsed entities and properties with detailed progress."""
        
    def _generate_embeddings_batch(self, items: List[dict], item_type: str) -> None:
        """Generate embeddings for titles and definitions in batches with progress logging."""
```

### 8.2.3.2 Key Methods Implementation

#### 8.2.3.2.1 Data Download and Parsing
- Use `requests` library with progress reporting for download
- Parse JSON-LD using standard JSON library (schema.org provides clean JSON-LD)
- Validate data structure before processing
- Handle potential download failures gracefully
- Log detailed progress during download and parsing phases

#### 8.2.3.2.2 Entity vs Property Classification
- **Entities**: Items with `@type` containing `"rdfs:Class"` or inheriting from schema.org classes
- **Properties**: Items with `@type` containing `"rdf:Property"` or property-related types
- Extract relationships based on schema.org vocabulary (`rdfs:subClassOf`, `schema:domainIncludes`, etc.)

#### 8.2.3.2.3 Embedding Generation
- Generate embeddings for all titles and definitions using existing `generate_embedding()` function
- Process in batches to manage memory usage
- Log detailed progress for user feedback during initial population and refresh operations
- Report progress as: "Processing embeddings: X/Y entities, Z/W properties"

#### 8.2.3.2.4 Database Backup Strategy
- Before any refresh operation, create backup of existing database to `schemaorg.db.backup`
- Only proceed with refresh if backup creation succeeds
- Restore from backup if refresh operation fails
- Clean up old backup files (keep only most recent backup)

## 8.2.4 Service Layer

### 8.2.4.1 SchemaOrgService Class

Business logic layer that interfaces between the API and the manager.

```python
class SchemaOrgService:
    def __init__(self, manager: SchemaOrgManager):
        self.manager = manager
        
    def search_entities(self, 
                       query: Optional[str] = None,
                       parent_id: Optional[str] = None,
                       limit: int = 50,
                       offset: int = 0) -> Dict[str, Any]:
        """Search entities with pagination and filtering."""
        
    def get_entity(self, identifier: str) -> Optional[Dict[str, Any]]:
        """Get specific entity by identifier."""
        
    def search_properties(self,
                         query: Optional[str] = None,
                         domain_includes: Optional[str] = None,
                         range_includes: Optional[str] = None,
                         limit: int = 50,
                         offset: int = 0) -> Dict[str, Any]:
        """Search properties with pagination and filtering."""
        
    def get_property(self, identifier: str) -> Optional[Dict[str, Any]]:
        """Get specific property by identifier."""
        
    def semantic_search(self,
                       query: str,
                       search_type: str = "both",  # "entities", "properties", "both"
                       limit: int = 20,
                       similarity_threshold: float = 0.7) -> Dict[str, Any]:
        """Perform semantic search using embeddings."""
```

### 8.2.4.2 Search Implementation Details

#### 8.2.4.2.1 Text Search
- Use SQLite FTS5 full-text search on title and definition fields
- Support partial matching and relevance scoring
- Combine with traditional WHERE clause filtering

#### 8.2.4.2.2 Semantic Search
- Generate embedding for search query using same model as data
- Use sqlite-vec for cosine similarity search against title and definition embeddings
- Return results above similarity threshold, ordered by relevance
- Support searching entities only, properties only, or both

#### 8.2.4.2.3 Hierarchical Browsing
- Leverage parent-child relationships for browsing entity hierarchies
- Provide endpoints to get children of an entity
- Support breadcrumb navigation up the hierarchy

### 8.2.5.3 Endpoint Specifications

#### 8.2.5.3.1 GET /api/schema-org/status
- **Purpose**: Get current status of schema.org database
- **Response**: `SchemaOrgStatus`
- **Behavior**: 
  - Auto-initialize database if not present
  - Return counts, last update time, file size

#### 8.2.5.3.2 POST /api/schema-org/refresh
- **Purpose**: Force refresh of schema.org data
- **Parameters**: `force: bool = False`
- **Response**: `{"success": bool, "message": str, "backup_created": bool}`
- **Behavior**:
  - Create backup of existing database to `schemaorg.db.backup`
  - Download fresh data with progress logging
  - Validate and populate with detailed progress reports
  - Restore from backup if any step fails
  - Log all operations and errors comprehensively

#### 8.2.5.3.3 GET /api/schema-org/entities
- **Purpose**: Search and list entities with pagination
- **Parameters**:
  - `query: Optional[str]` - Text search query
  - `parent_id: Optional[str]` - Filter by parent entity
  - `limit: int = 50` - Page size
  - `offset: int = 0` - Page offset
- **Response**: `SearchResult[SchemaOrgEntityOut]`

#### 8.2.5.3.4 GET /api/schema-org/entities/{identifier}
- **Purpose**: Get specific entity by identifier
- **Parameters**: `identifier: str` - Schema.org identifier (URL-encoded)
- **Response**: `SchemaOrgEntityOut`
- **Behavior**: Include raw JSON in response and children count

#### 8.2.5.3.5 GET /api/schema-org/properties
- **Purpose**: Search and list properties with pagination
- **Parameters**:
  - `query: Optional[str]` - Text search query
  - `domain_includes: Optional[str]` - Filter by domain
  - `range_includes: Optional[str]` - Filter by range
  - `limit: int = 50` - Page size
  - `offset: int = 0` - Page offset
- **Response**: `SearchResult[SchemaOrgPropertyOut]`

#### 8.2.5.3.6 GET /api/schema-org/properties/{identifier}
- **Purpose**: Get specific property by identifier
- **Parameters**: `identifier: str` - Schema.org identifier (URL-encoded)
- **Response**: `SchemaOrgPropertyOut`

#### 8.2.5.3.7 GET /api/schema-org/search
- **Purpose**: Semantic search across all schema.org data
- **Parameters**:
  - `query: str` - Search query (required)
  - `search_type: str = "both"` - "entities", "properties", or "both"
  - `limit: int = 20` - Result limit
  - `similarity_threshold: float = 0.7` - Minimum similarity score
- **Response**: `SearchResult[Union[SchemaOrgEntityOut, SchemaOrgPropertyOut]]`

## 8.2.7 Error Handling

### 8.2.7.1 Error Scenarios and Responses

1. **Download Failures**
   - Network connectivity issues
   - Invalid or corrupt data
   - Return appropriate HTTP status codes with error details

2. **Database Issues**
   - Database corruption
   - Permission issues
   - Disk space problems
   - Graceful degradation with informative error messages

3. **Search Errors**
   - Invalid query parameters
   - Malformed identifiers
   - Return 400 Bad Request with validation details

### 8.2.7.2 Logging Strategy

- Use existing logger utilities (`utils.logger`)
- Log all major operations with detailed progress information:
  - **Download phase**: "Downloading schema.org data... X MB / Y MB (Z%)"
  - **Parsing phase**: "Parsing JSON-LD... Found X entities, Y properties"
  - **Database population**: "Populating database... X/Y entities processed"
  - **Embedding generation**: "Generating embeddings... X/Y items processed"
  - **Backup operations**: "Creating backup... Success/Failed"
- Include progress information for long-running operations
- Log errors with sufficient context for debugging
- Use appropriate log levels (INFO for progress, ERROR for failures, DEBUG for detailed operations)

## 8.2.8 Performance Considerations

### 8.2.8.1 Database Optimization

1. **Indexing Strategy**n
   - Index on `identifier` for quick lookups
   - Index on `title` for text searches
   - FTS5 virtual table for full-text search
   - Vector index for embedding similarity search

2. **Query Optimization**
   - Use appropriate LIMIT/OFFSET for pagination
   - Lazy load raw JSON only when needed
   - Cache common queries in memory

3. **Memory Management**
   - Process embeddings in batches during population
   - Use streaming for large file downloads
   - Implement connection pooling for concurrent requests

### 8.2.8.2 Initialization Strategy

- **Server startup initialization**: Automatically check and initialize schema.org database on application startup
- **Lazy population**: Only download/populate on first access if not done during startup
- **Background processing**: Long-running operations (download, embedding generation) run in background
- **Progress reporting**: Detailed progress logging for user feedback during all phases:
  - Download progress with transfer rate and ETA
  - Parsing progress with entity/property counts
  - Database population with batch progress
  - Embedding generation with completion percentages
- **Graceful handling**: Manage concurrent initialization requests without conflicts
- **Startup behavior**: Non-blocking initialization during server startup with status endpoint for progress monitoring

## 8.2.10 Integration Points

### 8.2.10.1 Application Startup

Integrate with existing application startup in `app.py`:

```python
# Initialize schema.org manager on startup
schema_org_manager = SchemaOrgManager()

# Auto-initialize schema.org database on server startup
@app.on_event("startup")
async def startup_event():
    if get_settings().SCHEMA_ORG_AUTO_INITIALIZE:
        logger.info("Auto-initializing schema.org database on startup...")
        # Run initialization in background to avoid blocking server startup
        import threading
        init_thread = threading.Thread(target=schema_org_manager.initialize)
        init_thread.daemon = True
        init_thread.start()

# Include router
app.include_router(schema_org_api.router)
```

### 8.2.10.2 Dependency Injection

Follow existing patterns for database session management:

```python
def get_schema_org_db():
    """Get schema.org database session for dependency injection."""
    session_local = schema_org_manager.get_session_local()
    db = session_local()
    try:
        yield db
    finally:
        db.close()
```

## 8.2.11 Deployment Considerations

### 8.2.11.1 File Management

- Schema.org database file should be included in backup strategies
- Backup file (`schemaorg.db.backup`) management:
  - Created before each refresh operation
  - Automatically cleaned up (keep only most recent backup)
  - Used for automatic recovery on refresh failure
- Consider file size (typically 10-50MB for schema.org data)
- Handle concurrent access during refresh operations
- Implement file locking to prevent corruption during operations

### 8.2.11.2 Update Strategy

- Periodic refresh capability (manual trigger initially)
- Future: implement scheduled updates
- Backup and rollback capability for failed updates
