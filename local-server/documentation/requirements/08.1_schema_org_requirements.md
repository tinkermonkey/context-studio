# 8.1 Schema.org Local Access

Ingest the `schema.org` dataset into a local sqlite database for quick searching and reference.

## 8.1.1 Automatic Population

Automatically check if the `schema.org` dataset is present by checking for the database file, and if it's not present, download the source file from `https://schema.org/version/latest/schemaorg-current-https.jsonld`, parse it into JSON, and then ingest it.

- The schema.org database should be separate from the core dataset database (`schemaorg.db`)
- The schema.org database does not need migrations or schema upgrades and the schema can be managed by sqlalchemy
- The system should automatically initialize the schema.org database on server startup if it doesn't exist
- Database population progress should be logged for user feedback during the ingestion process

## 8.1.2 Force Upgrade

Provide an ability to force a fresh pull, clean the local database file, and populate it fresh.

- API endpoint to trigger forced refresh: `POST /api/schema-org/refresh`
- Should backup existing database before refresh in case of failure to `schemaorg.db.backup`
- Should validate downloaded data before replacing existing database

## 8.1.3 Data Model

Create tables for entities (everything that's not a property) and properties:

**Entities**:
- `id` - internal primary key for local database references (String UUID)
- `identifier` - the `@id` value from schema.org (String, unique, indexed)
- `title` - the `rdfs:label` from schema.org data (String, indexed for search)
- `title_embedding` - the vector embedding of the title (BLOB)
- `definition` - the `rdfs:comment` from the schema.org data (Text)
- `definition_embedding` - the vector embedding of the definition (BLOB)
- `parent_identifier` - the `rdfs:subClassOf.@id` value of the parent entity (String, nullable)
- `parent_id` - the `id` value (from local db) of the parent entity (String FK, nullable)
- `created_at` - timestamp when record was created (DateTime)
- `raw` - the raw json from schema.org (without children) for this entity (JSON)

**Properties**
- `id` - internal primary key for local database references (String UUID)
- `identifier` - the `@id` value from schema.org (String, unique, indexed)
- `title` - the `rdfs:label` from schema.org data (String, indexed for search)
- `title_embedding` - the vector embedding of the title (BLOB)
- `definition` - the `rdfs:comment` from the schema.org data (Text)
- `definition_embedding` - the vector embedding of the definition (BLOB)
- `contributors` - JSON array of `schema:contributor.@id` values for this property (JSON, nullable)
- `domain_includes` - JSON array of `schema:domainIncludes.@id` values for this property (JSON, nullable)
- `range_includes` - JSON array of `schema:rangeIncludes.@id` values for this property (JSON, nullable)
- `inverse_of` - JSON array of `schema:inverseOf.@id` values for this property (JSON, nullable)
- `created_at` - timestamp when record was created (DateTime)
- `raw` - the raw json from schema.org for this property definition (JSON)

## 8.1.4 API Endpoints

Provide REST API endpoints for searching and accessing schema.org data:

- `GET /api/schema-org/status` - Get current status of schema.org database
- `POST /api/schema-org/refresh` - Force refresh of schema.org data
- `GET /api/schema-org/entities` - Search entities with pagination and filters
- `GET /api/schema-org/entities/{identifier}` - Get specific entity by identifier
- `GET /api/schema-org/properties` - Search properties with pagination and filters  
- `GET /api/schema-org/properties/{identifier}` - Get specific property by identifier
- `GET /api/schema-org/search` - Semantic search across all schema.org data

## 8.1.5 Search Capabilities

- Full-text search on titles and definitions
- Semantic search using embeddings for similarity matching
- Filtering by type (entities vs properties)
- Hierarchical browsing by parent-child relationships
- Cross-reference lookup (find entities that use specific properties)
