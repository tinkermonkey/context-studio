Based on consolidated PR review, address the following in **Error Handling & Production Observability**:

- **Logger completely silenced in production**: `/workspace/ux/src/api/utils/logger.ts:33` — `ApiLogger.log()` returns early with `if (!this.isDev) return;`, suppressing ALL log levels including errors. The packaged Tauri desktop app runs with `NODE_ENV=production`, making every `apiLogger.error()` a no-op.
- **extractItems silently returns empty array on unexpected response format**: `/workspace/ux/src/api/services/base.ts:191-208` — When the API response matches neither `ListResponse` (with `items`) nor `PaginatedResponse` (with `data`), the method logs a warning and returns `[]`. Combined with the silenced logger, this is an invisible failure in production — users see empty tables with no error.
- **Pipeline execution JSON parse failures silently produce fallback objects**: `/workspace/ux/src/api/services/pipelineExecution.ts:173-180,198-205,222-229` — Three identical bare `catch {}` blocks silently fall back when LLM returns malformed JSON, losing structured data (reasoning, discrepancies) with zero indication.
- **isSystemHealthy catches all errors with bare catch**: `/workspace/ux/src/api/services/llmTraceability.ts:335-343` — Discards the actual error entirely. Network failures, auth failures, and server crashes all produce identical "system is not healthy" with no diagnostic detail.
- **XSS vulnerability in useButterToast DOM fallback path**: `/workspace/ux/src/hooks/useButterToast.tsx:102` — The DOM fallback directly interpolates `message` into HTML via `innerHTML` without escaping. If a server error message contains HTML/JS, it executes in the user's browser.
- **Triple error message decoration produces garbled messages**: `/workspace/ux/src/api/services/base.ts:49-60` — Errors are mutated by the interceptor, then by `request()`, then by `withErrorContext()`, producing messages like `"Taxonomy list: TaxonomyService: Bad Request"`.
