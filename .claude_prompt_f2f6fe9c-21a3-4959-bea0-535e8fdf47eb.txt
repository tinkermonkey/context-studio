The existing `test_sql_builders.py` file is missing a top-level `import pytest` — add it to the imports at the top and remove the four inline imports. Per CLAUDE.md: "Always place all import statements at the top of the file."

- **Regex allows invalid SQL identifiers (trailing dots, consecutive dots)**: The pattern `^[a-zA-Z_][a-zA-Z0-9_.]*$` at `sql_builders.py:24` accepts inputs like `"column."`, `"a..b"`, and `"table."` which are not valid SQL identifiers. While these are not exploitable for injection, the issue requirement asks to "defensively validate inputs match a safe column name pattern." The regex should enforce that dots only appear between valid identifier segments. A stricter pattern would be: `^[a-zA-Z_][a-zA-Z0-9_]*(\.[a-zA-Z_][a-zA-Z0-9_]*)*$`. This ensures each dot-separated segment is itself a valid identifier. Add a test case for trailing dot / double dot rejection.
