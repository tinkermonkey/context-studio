# Phase 1: Local Change Management Design Document

## 1. Overview

### 1.1 Purpose
Design and implement the foundational local change management system for Context Studio, providing the core infrastructure for entity versioning, change tracking, and rollback capabilities using SQLite and the existing ChangeEvent system.

### 1.2 Scope
This phase establishes the MVP (Minimum Viable Product) for change management by implementing:
- Entity versioning system in SQLite
- Working/staged state tracking with ChangeEvent integration
- Basic diff generation between versions
- Rollback capability via event sourcing

### 1.3 Success Criteria
- Users can track all modifications to StructureNode and StructureNodeLink entities
- Complete version history is maintained for all managed entities
- Diff generation shows clear before/after comparisons
- Rollback functionality restores entities to any previous version
- Integration with existing ChangeEvent infrastructure is seamless

## 2. Technical Architecture

### 2.1 Database Schema Extensions

#### 2.1.1 Entity Versions Table
```sql
CREATE TABLE entity_versions (
    id TEXT PRIMARY KEY,                    -- UUID as TEXT
    entity_type TEXT NOT NULL CHECK (entity_type IN ('structure_node', 'structure_node_link')),
    entity_id TEXT NOT NULL,               -- References structure_nodes.id or structure_node_links.id
    version_number INTEGER NOT NULL,       -- Incremental version counter
    content TEXT NOT NULL,                 -- Full entity snapshot as JSON
    state TEXT NOT NULL CHECK (state IN ('WORKING', 'STAGED', 'PROPOSED', 'APPROVED', 'MERGED', 'REJECTED')),
    parent_version_id TEXT,                -- References entity_versions.id
    changeset_id TEXT,                     -- Future use, nullable for now
    author_id TEXT NOT NULL,               -- User identifier
    created_at TEXT NOT NULL,              -- ISO timestamp
    metadata TEXT,                         -- Additional metadata as JSON
    
    FOREIGN KEY (parent_version_id) REFERENCES entity_versions(id),
    UNIQUE(entity_type, entity_id, version_number)
);

CREATE INDEX idx_entity_versions_entity ON entity_versions(entity_type, entity_id);
CREATE INDEX idx_entity_versions_state ON entity_versions(state);
CREATE INDEX idx_entity_versions_created ON entity_versions(created_at);
```

#### 2.1.2 Working Tree State Table
```sql
CREATE TABLE working_tree (
    entity_type TEXT NOT NULL,
    entity_id TEXT NOT NULL,
    current_version_id TEXT NOT NULL,      -- Current working version
    canonical_version_id TEXT NOT NULL,    -- Last committed/merged version
    staged BOOLEAN DEFAULT FALSE,          -- Whether changes are staged
    modified_at TEXT NOT NULL,             -- Last modification timestamp
    
    PRIMARY KEY (entity_type, entity_id),
    FOREIGN KEY (current_version_id) REFERENCES entity_versions(id),
    FOREIGN KEY (canonical_version_id) REFERENCES entity_versions(id)
);

CREATE INDEX idx_working_tree_staged ON working_tree(staged);
CREATE INDEX idx_working_tree_modified ON working_tree(modified_at);
```

#### 2.1.3 ChangeEvent Integration
```sql
-- Extend existing change_events table
ALTER TABLE change_events ADD COLUMN version_id TEXT;
ALTER TABLE change_events ADD COLUMN change_state TEXT CHECK (change_state IN ('WORKING', 'STAGED', 'PROPOSED', 'APPROVED', 'MERGED', 'REJECTED'));

CREATE INDEX idx_change_events_version ON change_events(version_id);
CREATE INDEX idx_change_events_state ON change_events(change_state);
```

### 2.2 Core Classes and Services

#### 2.2.1 Version Manager
```python
from typing import Optional, List, Dict, Any
from datetime import datetime
from dataclasses import dataclass
from enum import Enum

class ChangeState(Enum):
    WORKING = "WORKING"
    STAGED = "STAGED"
    PROPOSED = "PROPOSED"
    APPROVED = "APPROVED"
    MERGED = "MERGED"
    REJECTED = "REJECTED"

@dataclass
class EntityVersion:
    id: str
    entity_type: str
    entity_id: str
    version_number: int
    content: Dict[str, Any]
    state: ChangeState
    parent_version_id: Optional[str]
    changeset_id: Optional[str]
    author_id: str
    created_at: datetime
    metadata: Optional[Dict[str, Any]] = None

class VersionManager:
    def __init__(self, db_connection):
        self.db = db_connection
    
    def create_version(self, entity_type: str, entity_id: str, content: Dict[str, Any], 
                      author_id: str, state: ChangeState = ChangeState.WORKING) -> EntityVersion:
        """Create a new version of an entity."""
        
    def get_entity_versions(self, entity_type: str, entity_id: str) -> List[EntityVersion]:
        """Get all versions of an entity ordered by version number."""
        
    def get_current_version(self, entity_type: str, entity_id: str) -> Optional[EntityVersion]:
        """Get the current working version of an entity."""
        
    def get_canonical_version(self, entity_type: str, entity_id: str) -> Optional[EntityVersion]:
        """Get the canonical (last committed) version of an entity."""
        
    def rollback_to_version(self, entity_type: str, entity_id: str, 
                           version_number: int, author_id: str) -> EntityVersion:
        """Rollback entity to a specific version."""
```

#### 2.2.2 Working Tree Manager
```python
@dataclass
class WorkingTreeEntry:
    entity_type: str
    entity_id: str
    current_version_id: str
    canonical_version_id: str
    staged: bool
    modified_at: datetime

class WorkingTreeManager:
    def __init__(self, db_connection, version_manager: VersionManager):
        self.db = db_connection
        self.version_manager = version_manager
    
    def get_working_changes(self) -> List[WorkingTreeEntry]:
        """Get all entities with working changes."""
        
    def get_staged_changes(self) -> List[WorkingTreeEntry]:
        """Get all staged changes."""
        
    def stage_entity(self, entity_type: str, entity_id: str) -> bool:
        """Stage an entity for commit."""
        
    def unstage_entity(self, entity_type: str, entity_id: str) -> bool:
        """Remove an entity from staging."""
        
    def discard_working_changes(self, entity_type: str, entity_id: str) -> bool:
        """Discard working changes, revert to canonical version."""
        
    def is_entity_modified(self, entity_type: str, entity_id: str) -> bool:
        """Check if entity has working changes."""
```

```python
@dataclass
class EntityDiff:

    def generate_working_diff(self, entity_type: str, entity_id: str) -> EntityDiff:
        """Generate diff between working version and canonical version."""
        
    def generate_staged_diffs(self) -> List[EntityDiff]:
        """Generate diffs for all staged entities."""
```

## 3. API Endpoints

### 3.1 Version Management Endpoints
```python
# Get version history for an entity
GET /api/entities/{entity_type}/{entity_id}/versions
Response: List[EntityVersion]

# Get specific version of an entity  
GET /api/entities/{entity_type}/{entity_id}/versions/{version_number}
Response: EntityVersion

# Get diff between versions
GET /api/entities/{entity_type}/{entity_id}/diff?before={version}&after={version}
Response: EntityDiff

# Get diff between working and canonical versions
GET /api/entities/{entity_type}/{entity_id}/working-diff
Response: EntityDiff

# Rollback entity to specific version
POST /api/entities/{entity_type}/{entity_id}/rollback
Body: { "version_number": int, "author_id": str }
Response: EntityVersion
```

### 3.2 Working Tree Endpoints
```python
# Get all working changes
GET /api/changes/working
Response: List[WorkingTreeEntry]

# Get all staged changes
GET /api/changes/staged

# Stage entity changes
POST /api/changes/stage
Body: { "entity_type": str, "entity_id": str }
Response: { "success": bool }

# Unstage entity changes
DELETE /api/changes/stage/{entity_type}/{entity_id}
Response: { "success": bool }

# Discard working changes
POST /api/changes/discard
Body: { "entity_type": str, "entity_id": str }
Response: { "success": bool }
```

## 5. Performance Considerations

### 5.1 Storage Optimization
- Store full entity snapshots in JSON for simplicity in Phase 1
- Use SQLite's JSON functions for efficient querying
- Index on commonly queried fields (entity_id, state, created_at)

### 5.2 Query Optimization
- Use prepared statements for repeated operations
- Batch version creation operations where possible
- Limit version history queries with LIMIT clauses

### 5.3 Memory Management
- Stream large result sets instead of loading all into memory
- Use lazy loading for version content when not needed
- Implement pagination for version history endpoints

## 6. Error Handling

### 6.1 Version Conflicts
- Detect concurrent modifications during version creation
- Provide clear error messages for version conflicts
- Implement optimistic locking with version numbers

### 6.2 Data Integrity
- Use database transactions for multi-table operations
- Validate entity references before creating versions
- Handle corrupted version data gracefully

### 6.3 Rollback Safety
- Validate rollback permissions before execution
- Create backup version before rollback operation
- Prevent rollback to non-existent versions
