# 5.1 NLP Analysis UX

Continue building `NlpAnalysisPanel` to allow the user to select context from the reference APIs to refine the suggested `title` and `definition` for a node.

## 5.1.1 NLP Analysis Panel

The NLP analysis container component should enapsulates the NLP analysis sub-components, allowing the containing component to simply pass in a string for analysis.

The existing functionality of calling the analysis API endpoint to get the spacy based analysis.

### 5.1.1.1 Token Selection for Analysis

Tokens where `is_stop` == false should each have their own `token_nlp_analysis` component.

### 5.1.1.2 Token NLP Analysis Component

Create a `TokenNlpAnalysis` component which encompasses the following sub-components each of which should be built to MVP functionality:

- **TokenSenseList**: List the word senses in `wordnet.synsets` and allow the user to select the correct word sense, defaulting to the first match (they are listed by rank)

- **TokenConceptChart**: Chart the relationships uncovered by `concepcy.related_terms`
  - For each `related_term.relation` value, show the top n relations (default n=2)

  - The diagram should be similar to [05.99_concept_net_diagram.png](05.99_concept_net_diagram.png) which is an example of visualizing the nodes and links parsed by concepcy

### 5.1.1.3 Entity Component

Create a `NlpEntityAnalysis` component which details any matched entities.

- link to the reference source entity

- definition and other details

## 5.1.2 NLP Analysis Component Integration

The NlpAnalysisPanel should be integrated into the `layer`, `domain`, and `term` detail pages for both the `title` and `definition` elements. `TermDetails` is an example of integration for the `title`.
