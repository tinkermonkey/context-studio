# 02.2 Child Forms Design

## Overview

This design implements a seamless hierarchy creation workflow by enhancing existing forms to support parent context and integrating create child functionality into detail views. The design prioritizes user experience, data consistency, and maintainable code architecture.

## Architecture

### Form Component Enhancement

#### Enhanced Props Interface

```typescript
interface DomainFormProps {
  onSuccess?: (domain: DomainOut) => void;
  domain?: DomainOut; // For edit mode
  // Child form props
  parentLayerId?: string;
  parentLayer?: LayerOut; // Full object for better UX
  mode?: "create" | "edit" | "child";
}

interface TermFormProps {
  onSuccess?: (term: TermOut) => void;
  term?: TermOut; // For edit mode
  // Child form props
  parentDomainId?: string;
  parentDomain?: DomainOut;
  parentTermId?: string;
  parentTerm?: TermOut;
  mode?: "create" | "edit" | "child";
}
```

#### Form Behavior Logic

**Child Mode Detection:**

- `mode === 'child'` OR presence of parent props indicates child creation mode
- In child mode: hide parent selection controls, show only title and definition
- Auto-populate required parent fields in form state

**Context Display:**

- Show parent context header when in child mode
- Include parent title, type, and breadcrumb for clarity
- Use consistent iconography (Layers, Database, Hash icons)

### Modal Integration

#### Reusable Modal Component

```typescript
interface CreateChildModalProps {
  isOpen: boolean;
  onClose: () => void;
  title: string;
  children: React.ReactNode;
}

interface CreateChildButtonProps {
  parentType: "layer" | "domain" | "term";
  parentId: string;
  parentObject: LayerOut | DomainOut | TermOut;
  childType: "domain" | "term";
  onSuccess?: (child: any) => void;
}
```

#### Modal Workflow

1. User clicks create button in detail view
2. Modal opens with appropriate form in child mode
3. Form submits with parent context pre-filled
4. On success: modal closes, parent view refreshes, toast notification
5. On error: show inline error in modal, keep modal open

## Implementation Details

### Form State Management

#### Default Values Logic

```typescript
// Domain Form
const getDefaultValues = (domain?: DomainOut, parentLayerId?: string) => ({
  title: domain?.title ?? "",
  definition: domain?.definition ?? "",
  layer_id: domain?.layer_id ?? parentLayerId ?? "",
});

// Term Form
const getDefaultValues = (
  term?: TermOut,
  parentDomainId?: string,
  parentTermId?: string,
) => ({
  title: term?.title ?? "",
  definition: term?.definition ?? "",
  domain_id: term?.domain_id ?? parentDomainId ?? "",
  layer_id: term?.layer_id ?? "", // Auto-filled from domain
  parent_term_id: term?.parent_term_id ?? parentTermId ?? "",
});
```

#### Field Visibility Logic

```typescript
const shouldShowField = (
  fieldName: string,
  mode: string,
  hasParent: boolean,
) => {
  if (mode !== "child") return true;

  const hiddenInChildMode = ["layer_id", "domain_id", "parent_term_id"];
  return !hiddenInChildMode.includes(fieldName) || !hasParent;
};
```

### Data Flow

#### Create Child Workflow

1. **Detail View → Modal**
   - Pass parent object and type to CreateChildButton
   - CreateChildButton renders appropriate modal with form

2. **Form Submission**
   - Form validates with parent context
   - Submit includes pre-filled parent IDs
   - Success triggers cache invalidation

3. **State Updates**
   - TanStack Query invalidates related queries
   - Parent detail view automatically refreshes
   - Toast notification confirms success

#### Cache Management

```typescript
// Invalidate related queries after child creation
const invalidateRelatedQueries = (
  parentType: string,
  parentId: string,
  childType: string,
) => {
  queryClient.invalidateQueries({
    queryKey: [parentType, parentId],
  });
  queryClient.invalidateQueries({
    queryKey: [childType],
  });

  // Invalidate specific list queries
  if (childType === "domain") {
    queryClient.invalidateQueries({
      queryKey: ["domains", { layer_id: parentId }],
    });
  } else if (childType === "term") {
    queryClient.invalidateQueries({
      queryKey: ["terms", { domain_id: parentId }],
    });
  }
};
```

## Validation and Error Handling

### Client-Side Validation

#### Required Field Validation

- Title: Required, 2-255 characters
- Definition: Required, 1-2000 characters
- Parent relationships: Auto-validated in child mode

#### Relationship Validation

- Ensure parent exists and is accessible
- Validate parent-child type compatibility
- Check for circular dependencies in term hierarchies

### Error States

#### Form Errors

- Field-level validation errors
- Network/server errors
- Parent relationship errors

#### Modal Error Handling

- Keep modal open on form errors
- Show error toast for network issues
- Provide retry mechanism for transient failures

### Optimistic Updates

- Immediately add new child to parent view

- Reuse existing modal components
- Share validation logic between forms
- Minimize additional dependencies
