```python
class AttributeValueType(str, Enum):
    STRING = "string"
    NUMBER = "number"
    BOOLEAN = "boolean"
    DATE = "date"
    URL = "url"

class StructureNodeAttribute(BaseModel):
    key: str = Field(..., pattern="^[a-z][a-z0-9_]*$", description="Underscore-delimited identifier")
    title: str = Field(..., min_length=1, description="Human-readable display name")
    value_type: AttributeValueType = Field(..., description="Type constraint for values")
    value: Optional[Any] = Field(None, description="The actual attribute value")
    
    @validator("value")
    def validate_value_type(cls, v, values):
        """Validate value matches declared value_type"""
        if v is None:
            return v
        value_type = values.get("value_type")
        if value_type == AttributeValueType.STRING:
            return str(v)
        elif value_type == AttributeValueType.NUMBER:
            if not isinstance(v, (int, float)):
                raise ValueError("Value must be numeric")
            return v
        elif value_type == AttributeValueType.BOOLEAN:
            if not isinstance(v, bool):
                raise ValueError("Value must be boolean")
            return v
        elif value_type == AttributeValueType.DATE:
            # Validate ISO 8601 format
            import re
            if not re.match(r'^\d{4}-\d{2}-\d{2}', str(v)):
                raise ValueError("Date must be ISO 8601 format")
            return str(v)
        elif value_type == AttributeValueType.URL:
            # Basic URL validation
            if not str(v).startswith(('http://', 'https://')):
                raise ValueError("URL must start with http:// or https://")
            return str(v)
        return v

class ResolvedAttribute(StructureNodeAttribute):
    inherited: bool = Field(False, description="True if inherited from ancestor")
    source_node_id: Optional[UUID] = Field(None, description="ID of the node defining this attribute")
```

## System Architecture

The structure node attribute system extends Context Studio's existing knowledge graph model with typed metadata that flows through the parent-child hierarchy. The design leverages established patterns from the codebase's existing JSON field implementations (`reference_links` and `word_senses`) while adding hierarchical inheritance semantics.

### Data Model Extension

The `structure_nodes` table receives an `attributes` JSON column stored as TEXT (consistent with `reference_links` and `word_senses` patterns at `/workspace/local-server/database/models.py:75-76`). Each attribute conforms to this Pydantic model:

```python
class StructureNodeAttribute(BaseModel):
    key: str          # underscore_delimited identifier
    title: str        # Human-readable display name  
    value_type: str   # Constrained enum: string|number|boolean|date|url
    value: Optional[Any] = None  # The actual attribute value
```

**Value Type Selection**: Schema.org uses 43 primitive types while DBpedia uses 27. Both are overly complex for this use case. The selected five types (string, number, boolean, date, url) align with JSON primitives and cover the practical metadata needs without introducing parsing complexity. These map to:
- `string` → any text value
- `number` → integer or float (JSON number)
- `boolean` → true/false
- `date` → ISO 8601 format strings
- `url` → RFC 3986 compliant URLs

### Inheritance Resolution

The attribute inheritance system uses the existing `get_node_ancestors()` method in `NodeService` (`/workspace/local-server/services/node_service.py:490-511`) to traverse the hierarchy. Resolution follows nearest-ancestor precedence:

1. Query node's local `attributes` JSON array
2. Traverse to parent via `parent_node_id`
3. Collect parent attributes, marking each with `inherited=True`
4. Continue until `parent_node_id` is null (layer level)
5. Merge attributes with child values overriding ancestor values for matching keys

This approach reuses the existing recursive traversal pattern used for term uniqueness validation (`_get_domain_ancestor` at line 747).

## Scalability Design

### Performance Considerations

- **Depth Traversal**: Structure node hierarchies are shallow by design (layer → domain → term, max 3 levels with nested terms adding minimal depth). The existing `get_node_ancestors()` method already handles this efficiently.
- **JSON Parsing**: SQLite's JSON functions (`json_each`, `json_extract`) enable database-level filtering for attribute queries without loading all nodes, following the pattern established in `get_nodes_with_reference_link()` at `/workspace/local-server/services/reference_link_service.py:276-290`.
- **Caching**: Resolved attributes can be cached at the API layer since attribute changes are infrequent and the graph cache invalidation pattern already exists (`invalidate_graph_cache()` calls throughout the API).

### Query Optimization

The attribute resolution endpoint should use a single CTE query to traverse ancestors rather than multiple database round-trips. SQLite's recursive CTE support enables efficient hierarchical queries:

```sql
WITH RECURSIVE ancestors AS (
    SELECT id, parent_node_id, attributes FROM structure_nodes WHERE id = :node_id
    UNION ALL
    SELECT s.id, s.parent_node_id, s.attributes 
    FROM structure_nodes s 
    JOIN ancestors a ON s.id = a.parent_node_id
)
SELECT * FROM ancestors;
```
